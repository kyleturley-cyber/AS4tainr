# Known fidelity gaps

These are places where as4tainr knowingly behaves differently from IBM i. Each one should eventually turn into a fix with a test, or into a documented decision.

| Area | IBM i behavior | as4tainr today | Impact |
| --- | --- | --- | --- |
| Key collating sequence | Character keys are ordered by EBCDIC: lowercase before uppercase, and letters before digits | Byte order of UTF-8 text (`COLLATE "C"`): digits before uppercase before lowercase | Mixed letter/digit or mixed-case keys read in a different order. Planned fix: an EBCDIC sort key per character key field |
| Record locking | Update files lock the record read until UPDATE, DELETE, the next read, UNLOCK or close; WAITRCD per file; SQL and record-level access respect each other's locks | RPG reads lock as on IBM i (see record-locks.md); one wait time for all files (`AS4TAINR_WAITRCD`, 60 seconds); SQL and CL neither take nor wait for record locks; free-form N/E extenders and UNLOCK are not seen | A SQL UPDATE can change a record a program has locked |
| Commitment control | `COMMIT`/`ROLBK` under journaling | Each operation autocommits | No rollback of partial work |
| Field types | A, P, S, B, I, U, F, L, T, Z, G, O, H...; DATFMT/TIMFMT; REFFLD, CCSID, COLHDG | A, P, S, B (1-18 digits), F (FLTPCN), H, G (UCS-2), L, T, Z (*ISO forms), with VARLEN, ALWNULL, DFT and ALIAS; J, E, O (DBCS), 5 and other keywords not yet. Field text only (no column headings) | Files using other types are rejected at CRTPF and CREATE TABLE |
| Source files and objects | Source physical files with SRCSEQ/SRCDAT/SRCDTA records; members added with ADDPFM, edited with SEU/RDi; programs compiled to machine code; CRTRPGPGM (RPG III), CRTCMD, CRTPRTF, CRTSRVPGM/CRTPGM (modules, service programs, binding directories) | Members are text (`as4tainr.source_members`), not records; CRTSRCPF, CRTPF/CRTLF/CRTDSPF, CRTBNDCL/CRTCLPGM (checked) and CRTBNDRPG and CRTSQLRPGI `OBJTYPE(*PGM)` (kept as source; compiled when created and when called) from SRCFILE/SRCMBR; DSPFD TYPE(*MBRLIST); DSPPFM of a member. No ADDPFM/RMVM/CHGPFM, no member editing; CRTSQLRPGI `OBJTYPE(*MODULE)` and its precompiler options; RPG III, CMD, PRTF, COBOL, modules and service programs are kept as source only | Command definitions, DDS printer files and service programs do not build yet |
| `as4tainr import` | (no IBM i equivalent; replaces SAVF/RSTLIB or a TOBi/BOB build) | Builds PF (loading CSV), LF, DSPF, CL and RPGLE members; include files (`*.rpgleinc`, `*.clleinc`) become stream files | See docs/import.md |
| RPG engine (R1-R5) | ILE RPG as compiled by CRTBNDRPG | Batch, interactive and printing programs, procedures and program calls: see docs/rpg-engine.md for what R1-R5 cover. Not yet: a program that stays active (no LR) keeps its storage and open files but not its record locks, its printer output is a new spooled file on each call, and a cycle program called again starts a new cycle; CALL from RPG to a CL program passes parameters as values (changes do not come back), QCMDEXC commands that show a screen, `OPTIONS(*VARSIZE : *STRING : *TRIM)`, procedure pointers, `RETURN` with a value in ON-EXIT after an abnormal end (the error goes on), commitment control, numeric O spec fields without an edit code print a trailing minus, PAGE is the printer's page number, READ of a display file record, program-described WORKSTN files, DSPLY without a response in an interactive job writes to the job's messages instead of showing a screen, other system APIs, field-record relation indicators, look-ahead fields, `L` and `R` (separate sign) data formats, floating point, pointers, numbers over 38 digits, `%CHAR` of a value below 1 shows no leading zero (to be checked against a real system) | Programs fail with "not supported by the native engine yet" (and CRTBNDRPG refuses programs that use what is not supported at compile time) |
| RPG exceptions and status | ILE RPG exception handling: status codes, PSDS, INFDS, *PSSR, INFSR and ENDSR return points; the overflow routine and fetch overflow; files declared in procedures | Status codes for the errors as4tainr raises (program: 00100-00121, 00202, 00211, 00401, 00402, 00907...; file: 00011, 00012, 01021, 01022, 01211, 01215, 01216, 01218, 01221, 01299 for other I/O errors; 09999 for errors with no RPG status). PSDS: *PROC, *STATUS, the previous status, statement, *ROUTINE, *PARMS, exception ID (40-46), the message text in place of the exception data (91-170), library, the last file in error and its status (175-243), job, dates and time, program and module, user; not set: 171-174, compile date and time, compiler level, source file (288-333), external error code, XML elements, internal job ID, system name. A file error does not change the PSDS status (only the file's). INFDS: file feedback 1-52 (*OPCODE position 21: F file name, R record format, I the cycle's implicit read); open feedback: ODP type, file, library, record and key length, member, number of records at open, access type, duplicate keys, rows and columns, overflow line; I/O feedback: write, read and other counts, record format, record length; device feedback: database relative record number (397), printer line and page (367, 369), display attention identifier (369). Updated after every operation (no blocking). *PSSR and INFSR: an error in the subroutine calls it again, up to 20 times, then the default handler; ENDSR *CANCL ends the program abnormally with its own message; halt indicators H1-H9 are not tested. Overflow: lines conditioned by the overflow indicator print once each time it comes on (on again while on is not new overflow); exception lines are not printed by the overflow routine, and an OR line needs no F of its own. Local files: a recursive call shares the file with the calls before it; LIKEFILE, file parameters and TEMPLATE files are not supported | Programs that look at positions not set, or rely on blocking, see blanks or zeros |
| CL programs | The full CL language and command set, parameters passed by reference | The subset in cl-programs.md; parameters by value; no files in CL (DCLF/RCVF), OVRDBF, RCVMSG, RTVSYSVAL; *DEC to *CHAR in CHGVAR gives digits with leading zeros (to be checked against a real system). CL `INCLUDE` (SRCSTMF, SRCMBR) is expanded when the program is created; DCLPRCOPT and COPYRIGHT are accepted and ignored; `TYPE(*PTR)`, `STG(*DEFINED)`/`DEFVAR` are not supported yet | Programs using unsupported statements fail at CRTBNDCL with the line number |
| SQL | DB2 for i SQL: views, ALTER TABLE, routines, commitment control, QSYS2 catalog views, all scalar functions and special registers | SELECT/VALUES/INSERT/UPDATE/DELETE, one at a time, autocommitted, with the translations in sql.md; PostgreSQL semantics otherwise (e.g. character comparison and sort order). Time constants need colons (`'09:15:00'`) and timestamp constants the form `'2026-01-01 08:30:00'` in statements (Db2 also takes `'09.15.00'` and `'2026-01-01-08.30.00.000000'`); times are shown as `HH:MM:SS` whatever the job's time format | Statements outside the subset fail with SQL0084 or SQL0104 |
| SQL data definition (R6) | CREATE/ALTER/DROP of tables, views, indexes, aliases, sequences, routines, triggers; foreign keys; RUNSQLSTM listings and options | CREATE TABLE (with identity columns), CREATE INDEX, CREATE VIEW, ALTER TABLE (one action at a time), DROP, LABEL ON and SET SCHEMA (see sql.md), from STRSQL, RUNSQL, RUNSQLSTM, embedded SQL and `as4tainr sql`. SQL names up to 128 characters in upper case (quoted names with lower case or special characters, and schema names over 10 characters, are not supported); generated system names are unique within the library at creation, as on IBM i, but are not reused or reassigned; SQL statements use a column's SQL name, not its system name (Db2 takes both); CHECK only uses the table's columns, constants, comparisons and LENGTH, TRIM, LTRIM, RTRIM, UPPER, LOWER, SUBSTR, ABS, MOD, COALESCE; COMMENT ON and column headings accepted and not kept; CCSID and FOR BIT DATA accepted and ignored; an index's record format is the table's unless RCDFMT names one; OR REPLACE drops the indexes over the table; views: a program reads a view in the order the query returns rows and cannot change records through it, view column types come from PostgreSQL (expressions without a length are VARCHAR(32740)), a view column gets its own system name rather than its table column's; ALTER TABLE: no ADD COLUMN ... BEFORE, character and numeric columns do not convert into each other, record format level checks do not exist (programs are compiled when called); RUNSQLSTM gives every SQL error severity 30, writes no listing, and does not run SELECT; DLTF of a source file not supported | Scripts using other statements report SQL0084 for them |
| Null values in programs | ALWNULL(*NO, *INPUTONLY, *USRCTL) from the control specification, CRTBNDRPG or CRTSQLRPGI COMPILEOPT; null-capable keys, data structures and parameters with %NULLIND; status codes for data mapping errors | ALWNULL from ctl-opt/H spec and CRTBNDRPG: *NO gives a data mapping error (CPF5035) when a record with a null field is read; *INPUTONLY reads the default value (blanks, zero, 0001-01-01, 00.00.00; to be checked against a real system); *USRCTL sets and reads %NULLIND for fields of externally described files and writes nulls. Not yet: COMPILEOPT on CRTSQLRPGI, null-capable key fields in CHAIN/SETLL with *USRCTL, %NULLIND on data structure subfields and parameters; DSPPFM shows a null as blank | Programs using those behave differently |
| RPG data types | Every ILE RPG type: UCS-2 (C) and graphic (G) of any CCSID, float, %CHAR of floats | Float (4 and 8 bytes) with %EDITFLT, %FLOAT and the external display form (%CHAR of a float uses that form too; to be checked); BINDEC of 10-18 digits (8 bytes); EXTBININT(*YES); UCS-2 and graphic fields (UTF-16), which become character data (CCSID 37) when used with it, so characters outside CCSID 37 are replaced; float values are kept as decimals of up to 38 digits between operations | Programs with very large or very small floats, or non-Latin text in UCS-2 fields, behave differently |
| Embedded SQL (R6) | SQLRPGLE precompiled by CRTSQLRPGI: static and dynamic statements with host variables, sensitive or insensitive cursors, commitment control | Statements run when reached, on a connection of their own; host variables put into the statement text as escaped values; cursors read every row at OPEN (insensitive: later changes are not seen); COMMIT(*CHG), COMMIT and ROLLBACK accepted but each statement is autocommitted; SELECT INTO with more than one row assigns the first and sets SQLCODE -811. Not yet: multi-row FETCH (`FOR n ROWS`), positioned UPDATE/DELETE (`WHERE CURRENT OF`), GET DIAGNOSTICS, CALL of procedures, DDL in programs, SQL procedures and functions, SQLERRD values other than (3), SQLWARN flags, statements checked at compile time | Unsupported statements set SQLCODE -84 (SQLSTATE 42612); errors in a statement show up only when it runs |
| ILE binding (R6) | Modules of any ILE language bound by copy, service programs by reference with signatures checked at activation; activation groups; exported data; UPDPGM, UPDSRVPGM, DSPPGM, DSPSRVPGM, WRKBNDDIRE; symbols are case-sensitive | RPG and CL modules (CRTRPGMOD, CRTCLMOD), kept as source and compiled at call time. Signatures are checked (MCH4431), *PRV blocks keep older ones valid. Activation groups: the default one (DFTACTGRP(*YES), until RCLRSC), named ones and QILE (until RCLACTGRP), *NEW, *CALLER; programs that end without LR stay active in them. Exported data (EXPORT/IMPORT) is copied between modules at each bound call (the same values, not the same storage: a pointer to it differs). CL procedures can call RPG procedures (CALLPRC); RPG cannot call a CL procedure, and CL modules cannot be in service programs. Symbols match without regard to case. No WRKBNDDIRE, DSPMOD, DSPPGM DETAIL options; DSPPGM and DSPSRVPGM show one list | Programs that rely on the same address for exported data, or on case-sensitive procedure names, differ |
| RPG III (RPG/400) | CRTRPGPGM compiles RPG/400 into an OPM program; CVTRPGSRC converts it to RPG IV with a conversion report and log file (QRNCVTLG) | CRTRPGPGM converts the source as CVTRPGSRC does (its /COPY members included) and creates an RPG IV program from it (attribute RPG); CVTRPGSRC writes the RPGLE member and lists the conversion messages. Not converted: named constants continued on more lines, record address files, `FMTS`; DEBUG and FREE are removed; the log file is not written; the converted program runs in the ILE engine (OPM differences such as the default activation group's behavior are not reproduced) | Rare RPG/400 constructs need a manual fix after CVTRPGSRC, as on IBM i |
| Free-form RPG (7.5) | Every built-in function and free-form statement | The built-in functions in rpg-engine.md. Not yet: pointers and storage (%ADDR is null, %ALLOC, %REALLOC, %STR), XML-INTO, XML-SAX, DATA-INTO, DATA-GEN (%XML, %DATA, %HANDLER, %PARSER, %GEN), %THIS. Dates are held in *ISO form whatever DATFMT says (DATFMT and TIMFMT change only %CHAR and %DATE formats written in the call); the system time is UTC; %STATUS gives 1299 for any file error; OVERLOAD chooses by the kind of each argument (number, character, date, time, timestamp, indicator), not by length; SND-MSG writes the message ID and data without a message file's text, %TARGET is ignored | Programs using these fail when they reach them |
| CVTRPGFREE | (no IBM i command) | Fixed-form RPGLE to free form; MOVE, MOVEL, MOVEA, LOOKUP, TESTx, GOTO/TAG/CABxx, CALL/PARM, KLIST, DO without an index, total calculations, primary files, I and O specifications stay fixed. Arithmetic that overflowed silently in fixed form ends with RNQ0103 in free form (reported per line) | Review the report before using a converted member |
| Logical files | Keyed and selected views over physical files, join logical files, several record formats, RENAME/CONCAT/SST, DYNSLT | One physical file per logical file, one record format, a subset of its fields, keys (DESCEND), select/omit with COMP/VALUES/RANGE/ALL, UNIQUE (see logical-files.md) | Join and multi-format logical files are rejected at CRTLF |
| CHAIN not found | No current record; next READ position is not well defined in all cases | The next READ starts at the searched key | Programs that rely on this undefined behavior may differ |
| Object names | National characters allowed in some CCSIDs | ASCII A–Z, 0–9, `$#@_.` only | |
| Null-capable fields | `ALWNULL` | Not supported | |
| Character data | EBCDIC CCSIDs (37, 500, ...) | UTF-8 in PostgreSQL | Hex constants and byte-level tricks (`%BITAND` on text) differ |
| DSPLY output | DSPLY writes to the job's external message queue (shown on the screen interactively) | Messages without a response go to the program's output: the Command Entry log, or standard output for `as4tainr call`; with a response, interactively, a reply screen is shown | Operator messages (QSYSOPR) come later |
| 5250 sessions | Many session and device options | 24x80 only; no TLS (992), no NEW-ENVIRON auto sign-on or device naming | Use only on trusted networks for now; telnet sends passwords in clear text |
| Browser terminal | A 5250 display station: Attn, SysReq, Print, Help on a field, Dup, Erase Input, cursor select, 27x132, DBCS, Save/Restore Screen | Display station in `core/src/web` (see web-terminal.md): 24x80 only; no Attn, SysReq or Print keys; Field+/Field− and right-adjust are simplified; mandatory enter/fill and field exit required are not enforced; no TLS of its own | Use a TLS reverse proxy outside trusted networks; programs that rely on Attn or SysReq can't be driven from the browser yet |
| Sign-on security | QMAXSIGN / QMAXSGNACN can disable the profile or the device | The connection closes after 3 failures; profiles are never disabled | Repeated guessing is slowed but not blocked across connections |
| Library list | System values QSYSLIBL and QUSRLIBL; product libraries (`PRD`); QTEMP is private to each job and empty at sign-on; DSPLIBL shows the ASP device | The system part is fixed (QSYS, QSYS2, QHLPSYS, QUSRSYS); the user part comes from `AS4TAINR_LIBL`; no product libraries; QTEMP is one shared library; no ASP column; EDTLIBL is missing | Objects put in QTEMP are visible to other jobs and are not deleted at sign-off |
| Command entry | F4 prompting with help, F9 (all parameters), F10 (additional parameters), "+ for more values" on list parameters, job log, message queues | F4 prompts every parameter on one screen; list parameters are one text field; no help; messages shown in the session log only | Prompts look plainer; long lists are typed as `'a' 'b'` |
| CRTUSRPRF, CHGUSRPRF | About 60 parameters | USRPRF, PASSWORD, PWDEXP, STATUS, USRCLS, CURLIB, TEXT, SPCAUT, INLPGM, INLMNU (CHGUSRPRF: no PASSWORD, USRCLS or SPCAUT). `*SECADM` is needed for CRTUSRPRF, CHGUSRPRF, DLTUSRPRF and other users' DSPUSRPRF; object authority is in object-authority.md | No group profiles, job descriptions, output queues, LMTCPB or other attributes |
| Menus | MAIN and about 100 system menus; CRTMNU TYPE(*DSPF) (display file + message file of option commands) and TYPE(*UIM); GO with generic names and RTNPNT; F23 sets the initial menu; Attn shows the Attention program | as4tainr's own system menus (MAIN, USER, JOBS, FILES, PROGRAM, SECURITY) with as4tainr's texts; CRTMNU TYPE(*PGM) only; GO MENU only; no F23, no Attn; an initial menu that is not found opens Command Entry with a message | Menus of legacy apps built as *DSPF or UIM menus must be rewritten as *PGM menus (a program with a display file) for now |
| WRKOBJ | A list with options (2=Edit authority, 4=Delete, 5=Display, ...) | The list only; object types `*LIB` and `*FILE` | |
| DSPPFM | Shows the raw record image (zoned digits, packed as hex), F10/F11 hex view, position to line | Fields separated by a blank, numbers as decimal text, at most 9999 records; F19/F20 shift | Easier to read than the real one, but not identical |
| Password level (QPWDLVL) | Levels 0-3 change case rules, length (10 at 0/1, 128 at 2/3) and allowed characters | `AS4TAINR_QPWDLVL` sets case: 0/1 (default) not case sensitive, 2/3 case sensitive. Length is at most 28 at every level; allowed characters are not checked | A password valid on as4tainr may be too long or use characters IBM i rejects at level 0/1 |
| Jobs and subsystems | Subsystem descriptions, job queues, job descriptions, routing, priorities, holding, ENDJOB of active jobs, WRKSBS | Subsystems QINTER (sessions) and QBATCH (one job queue, first in first out) in the server process; JOBD is always QDFTJOBD; ENDJOB only for jobs still on the queue (see work-management.md) | Batch work runs, but cannot be scheduled, held or cancelled once running |
| Job logs and messages | Job logs are spooled (QPJOBLOG) at LOG level; message queues with inquiry messages, replies, break delivery, message files | Job logs are kept in the catalog for every job; user message queues with informational messages only; "message waiting" is shown on the command line message, not the MW indicator | No replies, no message files |
| Object authority | Owner, *PUBLIC, private authorities, authorization lists, group profiles, specific authorities, library authority, checked on every object access | Owner, *PUBLIC and private *ALL/*CHANGE/*USE/*EXCLUDE, *ALLOBJ; checked on file open and record changes, display files, CL CALL, data areas (see object-authority.md); RPG programs, libraries and SQL are not checked | A user can call any RPG program |
| Printer files and spooled files | Program-described and externally described printer files, cycle output (H/D/T), OA-OG, edit words, PRTCTL, output queue management, real printers | Program-described printer files with cycle output (H/D/T) and EXCEPT (E records), space/skip, edit codes 1-4 J-M Z Y, edit words, OFLIND, FORMLEN/FORMOFL (66 and 60 by default); spooled files with WRKSPLF/DSPSPLF/DLTSPLF (see spooled-files.md) | DDS printer files do not print yet |
| Data areas | `*CHAR`, `*DEC`, `*LGL` data areas; `*LDA`, `*GDA`, `*PDA`; lock waits end after the job's default wait time | `*CHAR`, `*DEC`, `*LGL` (see data-areas.md); the local data area `*LDA` (1024 characters per job, blanks when an interactive job starts, a copy of the submitter's for SBMJOB; CHGDTAARA, RTVDTAARA, DSPDTAARA; RPG data area data structures, IN and OUT). No `*GDA` (no group jobs) or `*PDA` (no prestart jobs): RPG fails with status 00402. `CHGDTAARA` waits for a `*LOCK` without a time limit; `RTVDTAARA` of a `*DEC` data area needs a `*DEC` variable; DSPDTAARA of `*LDA` shows it as text (packed or binary bytes show as the characters they are) | Group and prestart jobs cannot use their data areas |
| CL completion messages | Completion messages of commands run inside a CL program go to the program's message queue | They are shown in the job log after the CALL (e.g. "Data area ORDNXT created") | More messages on the command entry screen |
| Display files | Full DDS for display files | Common subset (see display-files.md): no `PUTOVR`/`OVRDTA`, `WINDOW`, `REF`/`REFFLD`, `VALUES`/`RANGE`/`COMP`, `EDTWRD`, help, `INDARA` | Programs using windows cannot run yet; validity checking keywords are not enforced |
| Subfiles | All subfile keywords | `SFL`, `SFLCTL`, `SFLSIZ`, `SFLPAG`, `SFLDSP`, `SFLDSPCTL`, `SFLCLR`, `SFLDLT`, `SFLEND(*MORE/*PLUS)`, `SFLNXTCHG`, `SFLMSG`, `PAGEUP`/`PAGEDOWN`. Not yet: `SFLRCDNBR` (the first page is always shown), `SFLINZ`, `SFLFOLD`/`SFLDROP`, `SFLLIN` (side-by-side records), `SFLCSRRRN`, message subfiles (`SFLMSGRCD`), `SFLEND(*SCRBAR)` shows as `*MORE` | Load-all and page-at-a-time subfiles work; position-to and folded lists do not |
| Display I/O operations | EXFMT, WRITE, READ, READC, CHAIN/UPDATE of subfile records | EXFMT, WRITE, READC, CHAIN and UPDATE of subfile records. Not yet: WRITE followed by a separate READ of a display file, `READ` of a WORKSTN file name, free-form `DCL-F` with `SFILE` | A WRITE is shown with the next EXFMT, not immediately; a program that writes a record and then waits (no input) shows nothing |
| Records on the screen | Input fields of every record on the screen can be typed into | Only the record being read (and its subfile) takes input; other records are output only | Rare in practice |
| Numeric display fields | Unedited output shows the field's digits; input positions follow the data type | Unedited output shows digits, a decimal point and a sign position | Screen layouts with unedited numeric fields can be wider by one or two positions |
| DATE / TIME constants | Job date in the job's date format; local time | MM/DD/YY and HH:MM:SS in UTC | |
