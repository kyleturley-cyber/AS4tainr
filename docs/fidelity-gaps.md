# Known fidelity gaps

These are places where as4tainr knowingly behaves differently from IBM i. Each one should eventually turn into a fix with a test, or into a documented decision.

| Area | IBM i behavior | as4tainr today | Impact |
| --- | --- | --- | --- |
| Key collating sequence | Character keys are ordered by EBCDIC: lowercase before uppercase, and letters before digits | Byte order of UTF-8 text (`COLLATE "C"`): digits before uppercase before lowercase | Mixed letter/digit or mixed-case keys read in a different order. Planned fix: an EBCDIC sort key per character key field |
| Record locking | Update files lock the record read until UPDATE, DELETE, the next read, UNLOCK or close; WAITRCD per file; SQL and record-level access respect each other's locks | RPG reads lock as on IBM i (see record-locks.md); one wait time for all files (`AS4TAINR_WAITRCD`, 60 seconds); SQL and CL neither take nor wait for record locks; free-form N/E extenders and UNLOCK are not seen | A SQL UPDATE can change a record a program has locked |
| Commitment control | `STRCMTCTL`/`ENDCMTCTL`, `COMMIT`/`ROLLBACK` (CL, RPG `COMMIT`/`ROLBK`, SQL) under journaling, lock levels *CHG/*CS/*ALL, commitment definitions per activation group or job | STRCMTCTL LCKLVL CMTSCOPE, ENDCMTCTL (pending changes rolled back with CPF8356; an interactive job is not asked, CPA8350), CL COMMIT/ROLLBACK (CPF8350 without a definition), RPG files with the COMMIT keyword (CPF4326 at open without a definition; status 00802 for COMMIT/ROLBK), embedded SQL with a commit level (CRTSQLRPGI COMMIT, SET OPTION COMMIT; SQL starts commitment control at the activation group), the job's end rolls back; see docs/sql.md. A definition is one PostgreSQL session with a transaction: other jobs never see pending changes (Db2 lets programs not under commitment control read them), the same job's files not under commitment control do not see them either and wait for (then time out on) records it changed; *CHG and *CS read committed data, *ALL is repeatable read; DDL is not part of the unit of work; no implicit commit when an activation group ends, no notify object (journals: see the Journals row); a program called with SBMJOB or QCMDEXC from RPG has its own definitions | Programs that read their own uncommitted changes through a file not under commitment control see the old data |
| Field types | A, P, S, B, I, U, F, L, T, Z, G, O, H...; DATFMT/TIMFMT; REFFLD, CCSID, COLHDG | A, P, S, B (1-18 digits), F (FLTPCN), H, G (UCS-2), L, T, Z (*ISO forms), with VARLEN, ALWNULL, DFT and ALIAS; J, E, O (DBCS), 5 and other keywords not yet. Field text only (no column headings) | Files using other types are rejected at CRTPF and CREATE TABLE |
| Source files and objects | Source physical files with SRCSEQ/SRCDAT/SRCDTA records; members added with ADDPFM, edited with SEU/RDi; programs compiled to machine code; CRTRPGPGM (RPG III), CRTCMD, CRTPRTF, CRTSRVPGM/CRTPGM (modules, service programs, binding directories) | Members are text (`as4tainr.source_members`), not records; CRTSRCPF, CRTPF/CRTLF/CRTDSPF, CRTBNDCL/CRTCLPGM (checked) and CRTBNDRPG and CRTSQLRPGI `OBJTYPE(*PGM)` (kept as source; compiled when created and when called) from SRCFILE/SRCMBR; DSPFD TYPE(*MBRLIST); DSPPFM of a member. No ADDPFM/RMVM/CHGPFM, no member editing; CRTSQLRPGI `OBJTYPE(*MODULE)` and its precompiler options; RPG III, CMD, PRTF, COBOL, modules and service programs are kept as source only. The system binding directories QC2LE and QUSAPIBD can be named and are empty: the C runtime and IFS procedures as4tainr provides bind without them (docs/ifs.md, docs/rpg-engine.md); others are not found (CPD5D02) | Command definitions, DDS printer files and service programs do not build yet |
| `as4tainr import` | (no IBM i equivalent; replaces a TOBi/BOB build) | Builds PF (loading CSV), LF, DSPF, CL and RPGLE members; include files (`*.rpgleinc`, `*.clleinc`) become stream files | See docs/import.md |
| RPG engine (R1-R5) | ILE RPG as compiled by CRTBNDRPG | Batch, interactive and printing programs, procedures and program calls: see docs/rpg-engine.md for what R1-R5 cover. Not yet: a program that stays active (no LR) keeps its storage and open files but not its record locks, its printer output is a new spooled file on each call, and a cycle program called again starts a new cycle; QCMDEXC commands that show a screen, `OPTIONS(*VARSIZE : *STRING : *TRIM)`, procedure pointers to procedures of other modules or service programs (procedures of the program, and the C runtime and CEE APIs, can be called through one), `RETURN` with a value in ON-EXIT after an abnormal end (the error goes on), commitment control as in the Commitment control row, numeric O spec fields without an edit code print a trailing minus, PAGE is the printer's page number, program-described WORKSTN files, DSPLY without a response in an interactive job writes to the job's messages instead of showing a screen, other system APIs, field-record relation indicators, look-ahead fields, `L` and `R` (separate sign) data formats, floating point, pointers, numbers over 38 digits, `%CHAR` of a value below 1 shows no leading zero (to be checked against a real system) | Programs fail with "not supported by the native engine yet" (and CRTBNDRPG refuses programs that use what is not supported at compile time) |
| RPG intermediate precision | The ILE RPG precision rules for numeric operations in every case: EXPROPTS(*RESDECPOS) and the (R) extender, 63-digit intermediate results | The rules' table for +, -, * and / (ILE RPG Reference, Precision of Intermediate Results) with the 30 digits IBM i 7.5 computes with (63 when an operand has more), as observed on PUB400: quotients get max(30 - ((L1 - D1) + D2), 0) decimals, literals count their own digits. as4tainr's numbers hold 38 digits, so a 63-digit intermediate result loses decimal places; EXPROPTS(*RESDECPOS) and (R) are not applied | Expressions with fields of more than 30 digits |
| RPG exceptions and status | ILE RPG exception handling: status codes, PSDS, INFDS, *PSSR, INFSR and ENDSR return points; the overflow routine and fetch overflow; files declared in procedures | Status codes for the errors as4tainr raises (program: 00100-00121, 00202, 00211, 00401, 00402, 00907...; file: 00011, 00012, 01021, 01022, 01211, 01215, 01216, 01218, 01221, 01299 for other I/O errors; 09999 for errors with no RPG status). PSDS: *PROC, *STATUS, the previous status, statement, *ROUTINE, *PARMS, exception ID (40-46), the message text in place of the exception data (91-170), library, the last file in error and its status (175-243), job, dates and time, program and module, user; the program's creation date and time (288-299, MMDDYY and HHMMSS) and its source file, library and member (304-333, for programs made with CRTBNDRPG); not set: 171-174, compiler level (300-303), external error code, XML elements (372-379), internal job ID, system name. A file error does not change the PSDS status (only the file's). INFDS: file feedback 1-52 (*OPCODE position 21: F file name, R record format, I the cycle's implicit read); open feedback: ODP type, file, library, record and key length, member, number of records at open, access type, duplicate keys, rows and columns, overflow line; I/O feedback: write, read and other counts, record format, record length; device feedback: database relative record number (397), printer line and page (367, 369), display attention identifier (369). Updated after every operation (no blocking). *PSSR and INFSR: an error in the subroutine calls it again, up to 20 times, then the default handler; ENDSR *CANCL ends the program abnormally with its own message; halt indicators H1-H9 are tested at *GETIN, when LR ends the program and at RETURN (RNQ0232, RNQ0233; the caller gets 00231), with as4tainr's message text and no inquiry message. Overflow: lines conditioned by the overflow indicator print once each time it comes on (on again while on is not new overflow); exception lines are not printed by the overflow routine, and an OR line needs no F of its own. Local files: a recursive call shares the file with the calls before it. LIKEFILE (the file takes the parent's device, usage and external description), TEMPLATE files (not opened) and LIKEFILE parameters to procedures of the same module (the caller's open file); not to programs or to procedures in other modules or service programs. EXTFILE (a literal, a variable at open, *EXTDESC): the file opened must have the same record format (not checked); EXTMBR is ignored | Programs that look at positions not set, or rely on blocking, see blanks or zeros |
| CL programs | The full CL language and command set, parameters passed by reference | The subset in cl-programs.md; parameters by reference as values copied back when the called program ends normally (a program that ends in error does not give back what it changed; the bytes of numbers are not shared, so a *DEC variable passed to a character parameter does not see its packed bytes). Program messages: RCVMSG from the program's own queue, its caller's and user message queues (no PGMQ(*EXT) or other programs by name; message queues are user profiles' and QSYSOPR, WAIT polls every half second), SENDER blank, no inquiry messages or replies; message keys are four printable characters (IBM's are binary); an exception caught from a command carries no message data (only its identifier and text), and an unmonitored error in a called CL program reaches the caller with its own identifier where IBM would end the program with a function check; the system message files (QCPFMSG...) have no descriptions, so a predefined system message's text is its message data or the text the job last saw for it; message data shorter than a FMT field leaves that variable empty (to be checked against a real system); SNDPGMMSG of an identifier missing from a message file fails with CPF2419. Files: DCLF needs the file when the program is created; RCVF/SNDF/SNDRCVF without subfiles, no record buffer variables. Overrides: OVRDBF TOFILE/LVLCHK/OVRSCOPE and OVRPRTF TOFILE/PAGESIZE/OVRFLW are honored, the other parameters (POSITION, SHARE, SECURE, OUTQ, COPIES, HOLD, SPLFNAME...) are accepted and ignored; an RPG program's files are found when it is called, so an override a program makes with QCMDEXC before opening a USROPN file does not change that file (it does for the programs it calls next); CLRPFM needs *CHANGE authority. RTVSYSVAL gives the shipped values, not ones a system administrator changed (no CHGSYSVAL), and the time zone is UTC. *DEC to *CHAR in CHGVAR gives digits with leading zeros (to be checked against a real system). CL `INCLUDE` (SRCSTMF, SRCMBR) is expanded when the program is created; DCLPRCOPT and COPYRIGHT are accepted and ignored. `STG(*DEFINED)` with `DEFVAR` over a `*CHAR` variable and `STG(*BASED)` with `BASPTR` work; pointers (`TYPE(*PTR)`, `ADDRESS`, `%ADDRESS`, `%OFFSET`) point at a variable and an offset in it, not at memory, so a based variable reaches only the storage of the variable its pointer was set to, and pointers cannot be passed to programs or procedures. A variable's value is substituted into a command as written, quoted when it has lower case letters | Programs using unsupported statements fail at CRTBNDCL with the line number |
| Commands (*CMD) | CRTCMD from command definition statements; the command analyzer, prompter and CPP interface | CMD, PARM, ELEM, QUAL (all keywords read); types *CHAR, *DEC, *LGL, *NAME, *SNAME, *CNAME, *GENERIC, *VARNAME, *HEX, *PNAME, *CMDSTR, *DATE, *TIME, *INT2/*INT4/*UINT2/*UINT4, *NULL, *ZEROELEM; DFT, CONSTANT, RSTD with VALUES, SPCVAL, SNGVAL, RANGE, REL, MIN, MAX, CASE, VARY, FULL; MAXPOS; VLDCKR (called first with the same parameters); CPP parameters in the documented form (lists with a 2-byte count, qualified names object first, mixed lists with their element count, lists of mixed lists with offsets). Not yet: DEP and PMTCTL (relations between parameters, conditional prompting), RTNVAL (return variables), PASSATR, PASSVAL, ALWVAR, CHOICEPGM, prompt override programs, PMTFILE/MSGF message prompts, REXX, CHGCMD and CHGCMDDFT; prompting a mixed list or a list shows it as one field | Commands that rely on those behave differently |
