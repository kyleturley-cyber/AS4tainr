# Known fidelity gaps

These are places where as4tainr knowingly behaves differently from IBM i. Each one should eventually turn into a fix with a test, or into a documented decision.

| Area | IBM i behavior | as4tainr today | Impact |
| --- | --- | --- | --- |
| Key collating sequence | Character keys, ORDER BY and comparisons of character columns follow the bytes of the field's CCSID (sort sequence *HEX, CCSID 37 here: blank and special characters, lowercase, uppercase, digits); SRTSEQ and ALTSEQ choose other sequences | Character columns have the collation `as4tainr.ebcdic37` (collate.rs: ICU rules listing CCSID 37 in byte order), so keyed reads, SETLL/SETGT, logical files, SQL ORDER BY and comparisons, MIN/MAX and indexes are in EBCDIC order; CL compares character values in EBCDIC too. But: characters CCSID 37 does not have sort after all of its own (IBM would have stored them as substitution characters); UCS-2 and graphic columns are in code point order; SRTSEQ, ALTSEQ and other CCSIDs' orders are not there; comparisons of two constants in SQL are still in byte order of Unicode text (lists of libraries, objects, members and output queues, as DSPLIB, WRKOBJPDM, WRKMBRPDM, QUSLOBJ, QUSLMBR and SAVLIB use them, are in EBCDIC order: AB before A1); PostgreSQL without ICU tailoring rules (before 16, or built without ICU) keeps byte order, and says so when the catalog is initialized. Databases made by earlier versions are changed when the catalog is initialized: every character column, with the views over them dropped and made again (definition, owner, privileges, comments, INSTEAD OF triggers), in one transaction | Applications sorting text that has characters outside CCSID 37 |
| Record locking | Update files lock the record read until UPDATE, DELETE, the next read, UNLOCK or close; WAITRCD per file; SQL and record-level access respect each other's locks | RPG reads lock as on IBM i (see record-locks.md); one wait time for all files (`AS4TAINR_WAITRCD`, 60 seconds); SQL and CL neither take nor wait for record locks; free-form N/E extenders and UNLOCK are not seen | A SQL UPDATE can change a record a program has locked |
| Commitment control | `STRCMTCTL`/`ENDCMTCTL`, `COMMIT`/`ROLLBACK` (CL, RPG `COMMIT`/`ROLBK`, SQL) under journaling, lock levels *CHG/*CS/*ALL, commitment definitions per activation group or job | STRCMTCTL LCKLVL CMTSCOPE, ENDCMTCTL (pending changes rolled back with CPF8356; an interactive job is not asked, CPA8350), CL COMMIT/ROLLBACK (CPF8350 without a definition), RPG files with the COMMIT keyword (CPF4326 at open without a definition; status 00802 for COMMIT/ROLBK), embedded SQL with a commit level (CRTSQLRPGI COMMIT, SET OPTION COMMIT; SQL starts commitment control at the activation group), the job's end rolls back; see docs/sql.md. A definition is one PostgreSQL session with a transaction: other jobs never see pending changes (Db2 lets programs not under commitment control read them), the same job's files not under commitment control do not see them either and wait for (then time out on) records it changed; *CHG and *CS read committed data, *ALL is repeatable read; DDL is not part of the unit of work; no implicit commit when an activation group ends, no notify object (journals: see the Journals row); a program called with SBMJOB or QCMDEXC from RPG has its own definitions | Programs that read their own uncommitted changes through a file not under commitment control see the old data |
| Field types | A, P, S, B, I, U, F, L, T, Z, G, O, H...; DATFMT/TIMFMT; REFFLD, CCSID, COLHDG | A, P, S, B (1-18 digits), F (FLTPCN), H, G (UCS-2), L, T, Z (*ISO forms), with VARLEN, ALWNULL, DFT and ALIAS; J, E, O (DBCS), 5 and other keywords not yet. Field text only (no column headings) | Files using other types are rejected at CRTPF and CREATE TABLE |
| Source files and objects | Source physical files with SRCSEQ/SRCDAT/SRCDTA records; members added with ADDPFM, edited with SEU/RDi; programs compiled to machine code; CRTRPGPGM (RPG III), CRTCMD, CRTPRTF, CRTSRVPGM/CRTPGM (modules, service programs, binding directories) | Members are text (`as4tainr.source_members`), not records; CRTSRCPF, CRTPF/CRTLF/CRTDSPF, CRTBNDCL/CRTCLPGM (checked) and CRTBNDRPG and CRTSQLRPGI `OBJTYPE(*PGM)` (kept as source; compiled when created and when first called in a process, the result kept while the process's view of the files, source members and, for sources that include stream files, the IFS has not changed: a file created again, deleted or given other fields, a changed member; a column's type changed in place with ALTER TABLE is seen only by a new process) from SRCFILE/SRCMBR; DSPFD TYPE(*MBRLIST); DSPPFM of a member. ADDPFM adds a member to a source file (CPC7305; CPF5812 then CPF7306 when it is there already), RMVM removes and CHGPFM changes one; ADDPFM to a data file is refused (CPF7306: one member per data file), EXPDATE and SHARE are accepted and not kept; no member editing; CRTSQLRPGI `OBJTYPE(*MODULE)` and its precompiler options; RPG III, CMD, PRTF, COBOL, modules and service programs are kept as source only. The system binding directories QC2LE and QUSAPIBD can be named and are empty: the C runtime and IFS procedures as4tainr provides bind without them (docs/ifs.md, docs/rpg-engine.md); others are not found (CPD5D02) | Command definitions, DDS printer files and service programs do not build yet |
| `as4tainr import` | (no IBM i equivalent; replaces a TOBi/BOB build) | Builds PF (loading CSV), LF, DSPF, CL and RPGLE members; include files (`*.rpgleinc`, `*.clleinc`) become stream files | See docs/import.md |
| RPG engine (R1-R5) | ILE RPG as compiled by CRTBNDRPG | Batch, interactive and printing programs, procedures and program calls: see docs/rpg-engine.md for what R1-R5 cover. Not yet: a program that stays active (no LR) keeps its storage and open files but not its record locks, its printer output is a new spooled file on each call, and a cycle program called again starts a new cycle; QCMDEXC commands that show a screen, procedure pointers to procedures of other modules or service programs (procedures of the program and of the modules bound into it, exported procedures of service programs, and the C runtime and CEE APIs, can be called through one), `RETURN` with a value in ON-EXIT after an abnormal end (the error goes on), commitment control as in the Commitment control row, numeric O spec fields without an edit code print a trailing minus, PAGE is the printer's page number, program-described WORKSTN files, DSPLY without a response in an interactive job writes to the job's messages instead of showing a screen, other system APIs, field-record relation indicators, look-ahead fields, `L` and `R` (separate sign) data formats, floating point, pointers, numbers over 63 digits, `%CHAR` of a value below 1 shows no leading zero unless DECEDIT('0.') or ('0,') (to be checked against a real system) | Programs fail with "not supported by the native engine yet" (and CRTBNDRPG refuses programs that use what is not supported at compile time) |
| RPG intermediate precision | The ILE RPG precision rules for numeric operations in every case: EXPROPTS(*RESDECPOS) and the (R) extender, 63-digit intermediate results | The rules' table for +, -, * and / (ILE RPG Reference, Precision of Intermediate Results) with the 30 digits IBM i 7.5 computes with (63 when an operand has more), as observed on PUB400: quotients get max(30 - ((L1 - D1) + D2), 0) decimals, literals count their own digits. as4tainr's numbers hold 63 digits (76 in a product before it is cut down), so a 63-digit intermediate result keeps its decimal places as far as 63 digits go; EXPROPTS(*RESDECPOS) and (R) are not applied | Expressions with fields of more than 30 digits |
| RPG exceptions and status | ILE RPG exception handling: status codes, PSDS, INFDS, *PSSR, INFSR and ENDSR return points; the overflow routine and fetch overflow; files declared in procedures | Status codes for the errors as4tainr raises (program: 00100-00121, 00202, 00211, 00401, 00402, 00907...; file: 00011, 00012, 01021, 01022, 01211, 01215, 01216, 01218, 01221, 01299 for other I/O errors; 09999 for errors with no RPG status). Local files: a recursive call shares the file with the calls before it. LIKEFILE (the file takes the parent's device, usage and external description), TEMPLATE files (not opened) and LIKEFILE parameters to procedures of the same module (the caller's open file); not to programs or to procedures in other modules or service programs. EXTFILE (a literal, a variable at open, *EXTDESC): the file opened must have the same record format (not checked); EXTMBR is ignored | Programs that look at positions not set, or rely on blocking, see blanks or zeros |
| CL programs | The full CL language and command set, parameters passed by reference | The subset in cl-programs.md; parameters by reference as values copied back when the called program ends normally (a program that ends in error does not give back what it changed; the bytes of numbers are not shared, so a *DEC variable passed to a character parameter does not see its packed bytes).
